# Judging Panel

### Priya Raman - Head of Developer Relations (Head Judge)

Head of Developer Relations at a large open-source foundation, with 14 years spent turning GitHub visitors into users.
She has reviewed thousands of READMEs and runs the foundation's "README clinic", where projects bring their front page for a teardown.

**Loves:** READMEs that make the value obvious in one screen and get a stranger from landing to a working result fast, with real output shown, not described.
**Hates:** Hype, vague promises ("blazing fast", "AI-powered insights"), invented badges, and walls of text above the fold that make you scroll before you know what the thing does.

### Tomás Ferreira - Principal Technical Writer

Documentation lead at a cloud platform company, with 18 years writing developer docs and the style guides other writers follow.
Known for being the contrarian in review: he checks every sentence against the code before he lets it ship.

Loves: docs where every claim can be traced to a file, function or output in the repo, and a structure that follows how readers actually skim (what it is, does it fit me, how do I run it).
Hates: marketing copy that drifts away from what the software actually does, and invented numbers, badges or benchmarks.

### Keiko Hart - Brand & Product Designer
Has designed launch pages and README visuals for developer tools at two startups; thinks in hierarchy, first-screen impact, and product-in-action imagery.
Reads a README the way a visitor does: scroll, squint, decide in five seconds whether to care.
**Loves:** visuals that show the real product doing its job, clear visual hierarchy, images big enough to read.
**Hates:** stock-looking banners, decoration that says nothing, screenshots too small to read.

### Marcus Webb - Staff Engineer, agent tooling

Staff engineer who builds and maintains Claude Code skills, MCP servers and automation scripts used daily by a 300-person engineering org.
Has watched too many skills work once on the author's machine and then fail silently for everyone else.

**Loves:** Skills an agent can follow cold with no guesswork; scripts that fail loudly with a clear message; explicit inputs, outputs and stop conditions.

**Hates:** Vague instructions, hidden dependencies, and steps that only worked once on the author's machine.

### Jess Alvarez - Audience Proxy (developer browsing GitHub)

Full-time backend developer who skims GitHub between tickets and decides in seconds whether a repo earns a star or a clone. Has tried a lot of tools that looked great on the landing page and died on the first `install` step.

Loves: a first screen that says what the thing does, who it is for, and the exact command to try it, with real output or a real screenshot instead of stock art.
Hates: badge walls, "seamlessly", "AI-powered" with no explanation, and having to scroll past three paragraphs of pitch to learn what the input and output are.

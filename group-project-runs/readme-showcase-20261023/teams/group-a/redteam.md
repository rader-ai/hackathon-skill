### 3. The opener oversells what the tool does (TRUTH/STORY, demo)
"turns speaker labeled call transcripts into an account timeline and a coaching report." In code, `run.py` only counts words, question marks and longest run, and checks quotes; the coaching content (summary, strengths, opportunities, quotes) comes from `analysis.json`, which the user must produce with the prompt and a model. In `demo()` it is simply `shutil.copyfile(examples/sample-analysis.json ...)`. The caption "shows measured talk share and question marks, with each quote checked" never says the quoted observations are a pre-written sample. A stranger who runs it on their own CSV gets metrics and an empty-looking report and thinks it is broken. Tomas's checks-against-code instinct hits this squarely.
- Demo fix: one sentence under the image: "The summary and quotes in this report come from examples/sample-analysis.json; the tool measures and verifies, it does not write the analysis." Opener: "...into an account timeline, measured talk statistics and a report that shows only quotes it verified against the transcript."
- Skill fix: add a Skeptic-pass rule to question-map.md: "for each output noun, find who produces it (code, user, model) and say so on the first screen." The current lint can't see this; the gate lets output_noun "coaching report" pass because it appears in a PINNED row.
